Guardian compatibility evidence — 2026-08-12, current Amp orb

Contract distinction
--------------------
Guardian is not a third dedicated Battlemon room mode. The validated tuples are:

  Guardian:             roomType=0, mode=2
  Battlemon Basic:      roomType=2, mode=0
  Battlemon Battle:     roomType=2, mode=1
  Invalid and rejected: roomType=2, mode=2

The native menu exposes Guardian Battle Mode separately from Battlemon Basic
Mode and Battlemon Battle Mode. Server create, quick-create, mode-change, and
start guards enforce the same matrix.

Guardian supports pets through its independent Allow Battlemon room option.
When that option is enabled, every active human must have one canonical,
alive, unexpired attached pet. For two humans, the gameplay actor topology is:

  position 0: QaLucy   (human endpoint 4)
  position 1: QaShua   (human endpoint 5)
  position 2: LucyPet  (owned by QaLucy)
  position 3: ShuaPet  (owned by QaShua)

Focused start regression
------------------------
RoomStartGamePacketHandlerTest.guardianBattlemonStartRequiresBothPetsAndAcceptsBothOwners
proves both sides of the admission contract:

  1. start with only QaLucy's pet attached is rejected before relay
     authorization or session creation;
  2. start with LucyPet and ShuaPet attached succeeds;
  3. the resulting session has gameplay positions [0, 1, 2, 3]; and
  4. relay authorization remains non-Battlemon and maps owner 4 to [0, 2]
     and owner 5 to [1, 3].

Guardian network endpoint contract
----------------------------------
Guardian retained two real relay endpoints. Packet 0x3EA and relay join state
were human-only:

  QaLucy recipient roster: [4, 5, 0, 0]
  QaShua recipient roster: [5, 4, 0, 0]

Both relay joins returned result 0. Pets were mapped as server-side gameplay
actors controlled by their owners; they were not represented as synthetic
network clients. This intentionally differs from dedicated Battlemon rooms,
which duplicate owner endpoint IDs for the pet actor positions.

Gameplay and lifecycle
----------------------
Both clients rendered QaLucy, QaShua, LucyPet, and ShuaPet in live Guardian
gameplay against Dokaro. The HUD tracked separate pet HP. Both pets eventually
reached 0/200 HP while the surviving humans continued the match, proving that
the pets were gameplay actors rather than room-only decorations.

The match completed naturally after approximately eleven minutes. The server
sent item rewards only for human positions 0 and 1:

Persistence
-----------
The before/after database snapshots show one Guardian loss recorded for each
human. Pet and PetStatistic rows were unchanged; no independent pet reward or
progression record was created.

Crash and error boundary
------------------------
The native dump inventory after the run was unchanged and contained only the
same older zero-byte controlled-exit placeholders. No new native dump was
created. The curated exception scan contains infrastructure failures from
earlier timestamps, but no game-server or relay-server exception during the
08:04–08:15 final match window.
